### v01에서 v02로 바꾼 이유와 실제 설정

v01은 서윤·지수의 디테일 저하와 서윤 디자인 변화에 대한 사용자 지적을 받았다. v02는 출력 1536×1024→**2560×1536**, TextEncode 참조 resolution 1024→**0(원본 유지)**, steps 40→**60**, 캐시 auto→**cpu/default**, 원본 얼굴 **384×384 크롭(x=320, y=0)**을 두 번째 실제 참조로 연결했다. CFG 1, Euler/simple, denoise 1은 유지했다.

참조 연결은 `LoadImage 7 → TextEncodeQwenImage21 16 images.image_1`, 같은 원본의 `ImageCrop 34 → images.image_2`다. 네 방향 구도는 빈 latent에서 생성한다. denoise를 낮추는 일반 img2img 가정으로 임의 재배선하지 않는다.

서윤 첫 HQ 출력은 **후면 보호대 누락**으로 보완 전 버전이다. 후면 패널을 실제 Qwen으로 편집하고 ComfyUI 합성 노드로 넣었으며 나머지 세 패널의 픽셀 변화 0을 기록했다. 도현 후면은 주머니 자세 지시와 달리 팔을 내렸지만 그 결과가 사용자 채택 디자인에 포함됐다. 자세는 가변 조건이다.

v02 실제 실행은 HQ 3회+서윤 보완 1회, 총 4회. 비교 갤러리·실제 프롬프트·워크플로우·참조 원본·노드 변경·실행/메타데이터 검증은 `삭제된_11초/visuals/turnaround_qwen_v02/`에 있다. 여러 옵션과 문구를 함께 바꿨으므로 단일 옵션 효과나 품질 향상률로 주장하지 않는다.

### 1차: 자체 기준 얼굴에서 네 상태 비교

GPT 4장+Qwen 4장: 중립, 눈물 고임, 미소 시작, 한쪽 눈물 흐름. 각 도구가 서로 다른 기준 얼굴을 사용했으므로 동일 얼굴의 엄밀한 A/B 비교는 아니다. Qwen 00002~00004는 접두사가 `B_00_neutral`이어도 실제 Edit 출력이다. 세 Edit 모두 첫 중립 PNG를 입력한 것은 메타데이터·해시로 확인했다. Qwen 조건별 시드는 서로 다르다.

검수 수정 사항: GPT의 얼굴 정체성은 대체로 유지했으나 피부가 밝고 붉어지고 머리카락·피부 질감이 부드러워졌다. 최초 긍정 판정을 후속 사용자 지적과 재검수에서 수정했다. 정확한 GPT 입력 연결은 파일만으로 확인하지 못했고, 제공된 선택 결과 외 총 생성 횟수는 알 수 없다.

기준 기록: `IMAGE_AB_REVIEW.md`, `IMAGE_METADATA.json`, `IMAGE_FIDELITY_CHECK.json`.

### 2차: 같은 원본·독립 편집·톤 보존 문구 비교

`COMMON_REFERENCE.png`를 두 도구에 공통 입력했다. v2 마지막 눈물 대조군 1장+톤/질감 보존 v3 감정 3장씩, 총 **8장**, 재생성 없이 조건당 첫 결과를 기록했다. A는 Codex 내장 `image_gen`이며 정확한 모델 버전 미노출. B는 실제 ComfyUI Desktop Qwen이다.

- A: 출력 1672×941, 시드 미노출, 같은 대화에서 원본을 독립 입력. 계획의 ‘매번 새 대화’ 조건은 충족하지 않았다.
- B: 출력 1536×864, 공통 시드 **50915118364261**. 실제 PNG 본문·시드·입력 해시를 대조했다.
- A의 v3 마지막 눈물은 피부색이 대조군보다 원본에 가까웠지만 중간 미소에 붉어짐이 남았다. 모든 감정 단계의 톤 보존 해결로 판단하지 않는다.
- B는 톤이 비교적 일정하지만 눈물 고임·미소 시작의 차이가 약했다. 선명하거나 규칙적인 질감을 원본 질감의 완전 보존으로 오해하지 않는다.
- 같은 원본을 독립 편집해도 톤 변화가 발생했으므로 누적 재입력만이 원인이라고 결론 내리지 않는다. 표본 1회이며 보존 문장의 인과 효과·재현성은 검증 전이다.

상세: `RESULTS.md`, `GENERATION_RECORD.json`, `TEST_PLAN.md`, `PREPARATION_RECORD.json`, `프롬프트/`, `워크플로우/`, `결과/GPT/`, `결과/Qwen/`.

이 실험은 정지 이미지 상태의 비교다. 눈물이 자연스럽게 흐르는 전환·영상 얼굴 유지·한국어 발음·목소리·감정 타이밍 검수는 수행하지 않았다.

## 7. 제작 지식의 출처와 적용 범위

- 툰킷 Threads/아카라이브 사례 분석은 `docs/AI_DRAMA_PRODUCTION_GUIDE.md`에 정리됐다. Threads 본문·첨부 확인 기록과 아카라이브 직접 접근 불가를 구분한다. 성과 수치는 작성자 주장이다.
- GPTERS 감정 연기 사례 분석 원답변은 `SOURCE_CONVERSATIONS.json`의 「감정 연기 영상 실험 분석」 마지막(가장 오래된) 턴에 있다. 원문: `https://www.gpters.org/media/post/create-emotional-acting-videos-P1t62u8T9Ocz1t3`.
- GPTERS 작성자의 이미지/영상/음악/편집 도구는 이 프로젝트의 확정 도구가 아니다. 완성 영상의 움직임·음성을 끝까지 검수한 분석도 아니다.
- 재사용할 것은 인물의 내적 억제, 표정·호흡 순서, 대사와 행동의 연결이다. 초근접·원테이크·10초 예시를 모든 샷에 강제하지 않는다.

## 9. 장면 연속성의 필수 인계

- 휴대전화 PROP_01: 서윤 → S#6 도현이 빼앗음 → S#7 경찰을 거쳐 서윤. 반환 중간 동작 설계 필요.
- 노트북 PROP_02: 식탁 고정, S#1 재생 → S#2 닫힘 → S#5 도현이 열어 마지막 프레임 확인 후 닫음.
- 보호대 PROP_03: 서윤 해부학적 왼손목, 지속 유지. S#6 잡히는 손목과 S#7 지수의 부축 동작을 설계한다.
- 장바구니 PROP_04: S#2 도현이 가져와 식탁에 둠. 죽·물·아이스크림은 일상 돌봄 소품이며 독극물 단서로 변경하지 않는다.
- 분리수거 봉지 PROP_06: S#4 서윤 → 도현 → 현관 옆 동선 밖에 내려놓음.
- 원본 메모리 카드 PROP_07: 수리점 보관 정보만 있음. 집에 실물로 추가하지 않는다.
- 도현은 처음부터 현관을 막고 있지 않다. S#4~6의 이동을 거쳐 출구를 가로막는다.
- S#1 블랙박스 영상의 마지막 실제 프레임을 S#5 화면에 재사용한다. 한글 메시지·파일명·00:11·UI는 별도 합성 제안이다.
- 서윤 외투·신발 상태는 S#4부터 S#7까지 연결. 마지막 엘리베이터 버튼은 오른손으로 누르는 계획이다.

위는 대본/설정상의 계획 상태다. 실제 영상 생성 후 관찰 상태를 따로 기록하고 차이를 다음 샷에 전달한다.

## 10. 남은 작업과 이어가기

이번 요청으로 완료할 범위는 인계 자료 정리다. Claude Code는 우선 현재 확정 사항을 읽고 후속 사용자 작업 지시를 이어받는다. 아래는 제작을 계속할 때의 미완료 목록이며 새 제작 실행 승인으로 해석하지 않는다.

1. 로케이션 시안의 사용자 선택과 문·가구·싱크·동선의 통일. 정확한 세트 기준과 현관/승강기 블로킹 정리.
2. 남성 지수 변경에 맞춘 부케·마지막 농담의 연출 검토, 대본 예상 길이와 11초 발화 실측.
3. 서윤 외투·신발, 도현 복구 영상 의상 등 장면별 상태 참조. 기타 등장인물 제작 범위는 후속 요청에 맞춤.
4. 실제 사용 환경에서 영상 모델·길이·참조 기능·한국어 오디오 방식을 확인하고 작품 룩/화면비·음성 ID 결정.
5. 확정 자산을 사용한 샷 설계·키비주얼·시작/종료 상태·대사/행동/소도구 대응 작성.
6. 감정 연기 영상의 작은 시험: 얼굴·룩 유지와 감정 전환·호흡·발화·눈물 타이밍을 실제 결과에서 확인.
7. 영상·음성 생성, 편집·화면 합성, 장면 연결·최종 결과 검수와 실패 원인 기록.

권장 첫 응답: 인계 파일을 읽은 뒤 “서윤 A·도현 D·남성 지수 B와 v02 디자인은 고정, 로케이션은 시안, 영상/음성은 미제작”을 확인하고 사용자의 다음 작업을 수행한다.
