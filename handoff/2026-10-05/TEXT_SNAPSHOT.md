| 색·노출 | 이마·볼의 붉어짐, 밝아짐, 배경 색과 대비 변화 |
| 미세 질감 | 피부 모공, 개별 머리카락, 블라우스 직물의 흐려짐·매끈해짐 |
| 감정 | 안도·기쁨이 읽히는지, 보존 지시 때문에 표정이 굳지 않는지 |
| 상태 구분 | 눈물 고임 → 미소 시작 → 한쪽 눈물 흐름이 구분되는지 |
| 원본 유지 | 얼굴 정체성·구도·시선·배경·빛 방향이 유지되는지 |
| 눈물 | 피부 표면에 자연스럽게 놓이는지, 눈·피부가 왜곡되지 않는지 |

원본과 출력 크기가 다를 수 있으므로 같은 표시 배율의 전체 화면과 얼굴 확대를 함께 확인한다. 원본 파일을 보정하거나 리사이즈해 덮어쓰지 않는다. 픽셀 지표는 영역 위치와 표정 변화의 영향을 받으므로 보조 근거로만 사용하고, 전반적인 화질 손실을 하나의 퍼센트로 단정하지 않는다.

v3가 성공하려면 톤·질감의 변화가 대조군보다 줄면서 의도한 표정과 눈물 상태가 살아 있어야 한다. 표정 변화에 수반되는 피부 움직임과 눈물 주변 변화는 오류로 세지 않는다.

같은 입력으로 바꾼 이번 테스트와 첫 테스트는 참조·대화 조건·시드가 다를 수 있다. 따라서 첫 결과 대비 개선을 전부 프롬프트 효과로 설명하지 않는다. 8장은 탐색 테스트이며 모델의 성공률이나 영상 연기 성능을 증명하지 않는다.

## 생성 기록

각 파일에 실제 입력, 제출 본문, 앱에 표시된 모델, 설정·시드, 출력 크기, 생성 횟수, 관찰 결과를 기록한다. GPT가 시드를 제공하지 않으면 미확인으로 남긴다. 눈에 띄는 차이가 확인되면 마지막 감정의 대조군/보강 쌍을 반복하는 후속 실험을 검토한다.

# 감정 표현 이미지 A/B — 첫 결과 검수

검수일: 2026-10-05
확인 범위: 사용자가 저장한 GPT 네 장과 Qwen 네 장의 실제 이미지, PNG 크기, Qwen의 내장 생성 기록. 영상·음성 검수는 하지 않았다.

## 핵심 판단

두 묶음 모두 눈물 맺힘, 작은 미소, 한 방울의 눈물을 구분해서 표현했다. 각 묶음 안에서 인물의 외형·헤어·의상·배경·조명도 대체로 유지된다. 이번 표본에서는 GPT의 표정 변화가 더 작고 절제돼 보이며, Qwen은 미소 단계의 입꼬리 변화가 더 뚜렷하다.

사용자의 톤·열화 지적 이후 GPT 원본을 재검수했다. 얼굴 동일성은 대체로 유지되지만, 피부가 단계별로 더 밝고 붉게 변하고 머리카락·피부의 미세 디테일이 원본보다 부드러워지는 문제가 있다. 앞선 판정은 이 변화를 작은 렌더링 차이로 과소평가했다. GPT 결과를 톤·질감까지 유지한 국소 편집 성공으로 판정하지 않는다.

두 묶음의 기준 인물이 서로 다르므로 같은 얼굴에서 편집 도구의 성능만 분리한 A/B 결과는 아니다. 각 도구의 자체 기준 얼굴에서 감정 표현과 얼굴 유지가 가능한지 보는 1차 결과로 기록한다. 제공된 선택 결과는 각 조건 한 장이며 실제 총 생성 횟수는 모른다.

## 파일과 상태 대응

Qwen은 PNG 내장 프롬프트를 대조해 아래 순서를 확인했다. GPT는 파일명과 실제 표정을 기준으로 대응했다.

| 상태 | GPT 파일 | Qwen 파일 |

| 00 중립 | 이미지/GPT/차분한 자연광의 여성 초상.png | 이미지/Qwen/B_00_neutral_00001_.png |
| 01 눈물 맺힘 | 이미지/GPT/눈물 어린 조용한 위로.png | 이미지/Qwen/B_00_neutral_00002_.png |
| 02 미소 시작 | 이미지/GPT/눈물 어린 따뜻한 미소.png | 이미지/Qwen/B_00_neutral_00003_.png |
| 03 눈물 흘림 | 이미지/GPT/감격의 미소와 눈물.png | 이미지/Qwen/B_00_neutral_00004_.png |

파일명의 B_00_neutral 접두사가 모든 Qwen 이미지에 남아 있지만, 00002~00004는 실제 감정 Edit다. 이름만으로 중립 생성이라고 분류하지 않는다. 원본 파일명은 보존했다.

| 조건 | GPT에서 관찰 | Qwen에서 관찰 | 테스트 목적에 따른 판단 |
| --- | --- | --- | --- |
| 00 중립 | 눈물 없는 편안한 얼굴. 입꼬리에 약한 부드러움이 있어 완전히 무표정한 인상은 아님. 얼굴이 프레임을 크게 차지함. | 눈물 없는 편안한 얼굴. 입꼬리가 살짝 부드러우며 GPT보다 어깨·배경이 많이 보임. | 두 장 모두 기준 이미지로 사용 가능. 구도가 달라 눈가의 미세 표현을 같은 조건으로 비교하기는 어려움. |

| 03 눈물 흘림 | 화면 왼쪽 볼에 한 방울과 가느다란 젖은 자국. 닫힌 입의 따뜻한 미소가 유지됨. | 화면 오른쪽 볼에 한 방울과 가느다란 젖은 자국. 닫힌 입의 미소가 유지됨. | 한쪽 볼의 한 방울이라는 지시는 두 결과 모두 관찰됨. 좌우는 지정하지 않았으므로 서로 다른 쪽에 생긴 것을 오류로 판정하지 않음. |

눈물의 선과 방울이 두 최종 이미지 모두 매우 또렷하다. 젖은 피부로 읽히지만 모양이 정돈돼 연출된 느낌도 있다. 자연스럽게 맺혀 흘러가는지는 정지 이미지로 확인할 수 없다.

## 얼굴과 고정 조건

- 두 묶음 안에서 눈·코·턱의 전체적인 특징, 헤어, 의상, 배경과 빛의 방향이 대체로 유지된다. 큰 얼굴 훼손, 치아 생성, 추가 인물은 관찰하지 않았다.
- GPT에는 표정 변화와 함께 피부 색감·명암·머리 윤곽과 미세 질감의 차이가 보인다. 피부는 단계별로 더 밝고 붉어지고, 피부·머리카락의 디테일은 원본보다 부드러워진다. 인물 교체로 보일 정도의 변화는 아니지만 톤·질감 보존은 불충분하다.
- Qwen의 전체 장면 배치는 안정적으로 보인다. 국소 표정 수정 외의 작은 렌더링 차이는 있어 원본 그대로라는 의미는 아니다.
- 두 기준 이미지 모두 시선이 렌즈에 가까워 보인다. 화면 밖 상대를 보는 시선으로 확정하려면 눈동자 방향을 추가로 설계할 필요가 있다.
- 02와 03의 미소 강도는 각 묶음 안에서 비슷하며, 가장 분명한 차이는 눈물의 위치다. 더 복잡한 감정 전환을 재현했다고 평가하지 않는다.

## 실제 생성 기록 확인

세부 기록은 IMAGE_METADATA.json에 저장했다. Qwen의 본문 네 개는 준비한 v2 .txt 파일과 일치한다. 세 Edit 모두 B_00_neutral_00001_.png를 참조하며, PNG에 기록된 입력 해시와 보관 중인 기준 파일의 SHA-256이 세 조건 모두 일치한다. 이전 감정 결과를 이어 편집한 구성은 아니다.

| 00 | 303617254009935 |
| 01 | 50915118364261 |

Qwen 공통 기록: 1536 × 864, steps 40, CFG 1, euler, simple, denoise 1, negative_prompt 빈 값, encoder resolution 1024. diffusion 파일명은 qwen_image_2.1_int8_convrot.safetensors, 인코더 파일명은 qwen3vl_8b_int8_convrot.safetensors로 기록돼 있다. 이 기록은 해당 PNG의 실행 그래프 정보이며 독립적인 모델 가중치 감식은 아니다.

GPT 파일은 모두 1672 × 941이고 생성 프롬프트·모델·참조 경로의 PNG 텍스트 기록은 없다. GPT Image 2.5라는 도구 표기는 사용자의 설명을 따른다. 표정과 얼굴 유지에 대한 시각 관찰은 가능하지만 정확한 입력 본문과 편집 연결은 PNG만으로 확인할 수 없다.

GPT에서 매 순간 같은 중립 파일을 참조했는지, 이전 결과를 이어 편집했는지는 사용자 답변 대기 중이다. Qwen은 조건마다 seed가 달라 표정 차이에 확률적 변화도 포함된다. 네 상태가 원하는 방향으로 나온 것은 관찰했으나 각 조건의 재현성을 확인한 것은 아니다.

## 다음 테스트 제안

### 재검수: GPT 톤과 디테일

원본 해상도로 중립과 마지막 이미지를 다시 확인하고, 네 단계의 고정 좌표 영역을 읽기 전용으로 측정했다. 측정 결과와 영역 정의는 IMAGE_FIDELITY_CHECK.json에 기록했다. 입력 이미지는 수정하지 않았다.

- 이마와 화면 오른쪽 볼의 평균 밝기·붉은 성분은 단계별로 증가한다. 표정과 눈물을 변경하는 지시만으로 피부 톤까지 유지됐다고 볼 수 없다. 얼굴 전체가 더 따뜻하고 밝아지는 시각 변화와도 일치한다.
- 볼과 머리카락 영역의 국소 디테일 지표는 원본보다 낮다. 미세 질감이 부드러워지는 관찰을 뒷받침하지만, 전체 화질의 열화율이나 정확한 손실 비율로 해석하지 않는다.
- 일부 영역의 지표는 마지막 단계에서 소폭 증가한다. 따라서 모든 영역에서 매 단계 단조롭게 화질이 나빠진다는 결론은 내리지 않는다. 톤의 누적 변화는 뚜렷하며 디테일은 원본보다 약해졌다는 수준으로 판단한다.
- 네 이미지의 픽셀 크기는 모두 같다. 해상도 유지와 실질적인 질감 유지가 별개임을 보여준다.
- 고정 좌표 측정은 정밀 정합 없이 수행했다. 얼굴의 작은 위치·표정 변화와 조명 재구성도 수치에 영향을 줄 수 있어 육안 관찰의 보조 자료로 사용한다.

이 결과만으로 원인을 이전 이미지의 연쇄 재입력이라고 확정하지 않는다. GPT의 실제 편집 연결은 아직 확인되지 않았다. 원본을 매번 독립적으로 첨부한 편집에서도 재생성·감정 해석·대화 문맥이 톤에 영향을 줬을 가능성은 별도 가설이다.

다음 비교에는 원본 대비 피부 톤·노출·배경 색·머리카락과 피부의 디테일 보존을 독립 검수 항목으로 추가한다. 같은 중립 파일을 매번 첨부해 독립 편집하고, 새 대화 조건을 사용했는지도 기록한다. 원래 v2 프롬프트와 이번 결과는 보존하며 수정 프롬프트를 쓰면 새 버전으로 비교한다.

아래는 제안이며 사용자 확정 또는 실행 결과가 아니다. 이번 결과를 검수한 뒤 기존 v2 프롬프트를 소급 수정하지 않았다.

1. 동일 얼굴 비교가 목적이면 기준 파일 하나를 A/B 두 도구에 공통으로 넣어 세 감정 Edit만 반복한다. 어느 모델에서 만든 참조인지 함께 기록한다.
2. 미소 단계의 제어가 목적이면 02의 아주 작은 입꼬리 변화와 03의 조금 더 분명한 볼·눈가 반응을 비교한다. 눈물만 달라지는지 표정 강도도 달라지는지를 별도로 확인한다.
3. 원래의 영상 연기 실험으로 넘어갈 때는 같은 영상 도구·같은 연기 프롬프트를 사용하고 시작·종료 참조 기능의 실제 지원을 확인한다. 중립에서 끝 상태로 자연스럽게 변화하는지, 얼굴과 눈물의 연속성·감정의 타이밍이 유지되는지 실제 영상에서 검수한다. 세 스틸의 정지 상태 성공을 영상 연기의 성공으로 대체하지 않는다.

## 3. 집의 기준 배치 — 신규 제안

모든 방위는 현관 안쪽에서 거실을 바라보는 기준으로 정의한다.

- 오른쪽에는 낮은 소파와 거실 공간. 창은 집 안쪽 끝에 있다.
- 식탁에서는 고개를 돌리면 현관 방향이 보인다. 주방에서는 식탁의 서윤과 휴대전화 쪽 움직임을 볼 수 있다.

- 서윤의 식탁 자리는 진입 통로 쪽 짧은 변에 둔다. 오른손으로 노트북과 휴대전화에 접근하고, 현관을 확인하는 동작이 가능하다.
- 현관문은 실내에서 바깥 복도 쪽으로 열리는 구조를 제안한다. 잠금 해제 후에도 문이 닫힌 위치에 있는 동안 도현이 안쪽에서 눌러 개방을 막을 수 있는 동작으로 검토한다.
- 도어록 내부 조작부는 문 옆 벽에 설치하지 않는다. 문짝 안쪽 손잡이 주변에 위치하고, 서윤의 오른손 접근 높이를 정한다.

실제 문 동작·두 사람의 팔 위치·경찰의 문밖 위치는 후속 블로킹에서 확인한다. 이 배치안만으로 클라이맥스의 동작 검수가 끝난 것은 아니다.

# 삭제된 11초 — 로케이션 이미지 v01

## 제작 기준

`../../LOCATION_BIBLE.md`와 `../../SCRIPT_BASELINE.md`를 기준으로 집, 공용 복도, 엘리베이터, 지하주차장을 제작한다. 주연이 등장하지 않는 빈 공간 이미지이며 인물 참조는 입력하지 않는다. 실사 드라마의 일반적인 현대 한국 아파트를 제안한다. 최종 룩·화면비 확정이라는 뜻은 아니다.

공간감은 가까운 문틀·가구·조리대, 중간 거리의 연기 영역, 먼 창·현관·벽이 중첩되는 구도로 설계한다. 원근선·읽히는 바닥·가구 사이의 빈 동선과 현실적인 방 크기를 함께 요구한다. 집은 현관에서 봤을 때 주방·식탁이 왼쪽, 소파가 오른쪽, 창이 안쪽에 있는 초안 구조다. 역방향에서는 화면 좌우가 반대로 나타나야 한다.

## 실제 도구와 파일

- 사용자 지정 Deno Qwen-Image 2.1 T2I + Edit의 기존 테스트 워크플로우 사본을 이용한다. 원본 워크플로우를 수정하지 않는다.
- 로컬 ComfyUI Desktop 서버에서 실행한다. 내장 이미지 도구나 외부 유료 API를 사용한 결과가 아니다.
- 설정: 2048×1152, KSampler 40 steps, CFG 1, Euler/simple, denoise 1, QwenImage21Cache cpu/default. 해상도·steps는 실제 노드 설정이다. 자연어 렌즈·광원 지시는 정확한 물리 제어값이 아니다.
- `prompts/`: 실제 입력한 프롬프트. `workflows/`: ComfyUI에서 열 수 있는 사본. `api/`: 실제 제출 노드 그래프. `outputs/`: 원본 PNG. `GENERATION_RECORD.json`: 실행 ID, 참조 연결, 출력 해시·크기·상태.
- 집 전체 HOME_MASTER는 T2I로 생성한다. 집 역방향, 주방, 현관은 HOME_MASTER의 실제 PNG를 LoadImage → TextEncodeQwenImage21의 `images.image_1`으로 입력한다. 복도는 T2I, 엘리베이터는 복도 PNG를 같은 슬롯으로 입력한다. 지하주차장은 별도 T2I로 생성한다. 참조 텍스트만으로 연결됐다고 가정하지 않는다.
- 편집 입력의 resolution=1536은 참조 이미지를 모델이 처리하는 크기 설정이며 파일 원본은 보존한다. 출력 해상도와 별개다.

## 생성·육안 검수

집 전체, 역방향, 주방, 현관, 복도, 엘리베이터, 지하주차장의 실제 생성 이미지와 보완본을 모두 육안 확인했다. 지하주차장 보완본에서는 빈 배경 요청과 달리 생성됐던 인물 두 명과 화면 상단 룸미러가 제거됐음을 확인했다. 전체 생성 11회에서 일곱 개 대표 뷰를 선정했다. 모두 검토용 제안이며 사용자 채택을 미리 확정하지 않는다.

# 삭제된 11초 — Qwen 턴어라운드 디테일 수정 v02

최종 상태: 2026-10-05 사용자가 현재 서윤·도현·지수 세 수정본을 모두 채택하고 인물 디자인을 고정했다. 기준 파일은 아래 추천 결과 세 장이며, 실제 파일·해시·고정 범위는 `FINAL_SELECTION.json`에 기록했다. 앞으로 얼굴·헤어·기본 의상·소도구·승인된 측면과 후면 디자인은 이 참조를 따른다. 자세·표정·행동은 장면에 맞게 변경한다.

사용자 피드백: 서윤·지수 v01은 퀄리티와 디테일이 낮고, 특히 서윤 디자인이 원본에서 달라졌다. v01을 최종 턴어라운드로 취급하지 않는다. 캐스팅 원본 서윤 A·지수 B는 그대로 확정 유지한다.

## 실제 노드 변경

| 노드 | v01 | v02 | 목적 |
| --- | --- | --- | --- |
| 10 DenoResolutionSetup | 1536×1024 | 2560×1536 | 실제 생성 픽셀 수 1.57MP → 3.93MP. 네 방향의 얼굴·옷에 더 많은 픽셀 배분 |
| 16 TextEncodeQwenImage21 resolution | 1024 | 0 | 1024×1536 입력 원본을 약 832×1248로 축소하던 동작을 해제하고 원본 크기로 유지 |
| 20 KSampler steps | 40 | 60 | 샘플링 단계 증가. 품질 개선의 보장이 아니라 결과 비교 항목 |
| 3 QwenImage21Cache | auto / default | cpu / default | 커진 참조에 대응하는 CPU 캐시. default는 노드 설명상 무손실 저장. v01도 default였으므로 정밀도 개선으로 주장하지 않음 |

빈 latent에서 네 방향 구도를 생성하는 구조이므로 denoise는 1을 유지한다. CFG 1, Euler/simple, 기존 모델·VAE·텍스트 인코더 및 비교용 시드를 유지한다. 텍스트의 `8K`, `ultra quality` 같은 단어로 옵션 변경을 대체하지 않는다.

서윤 프롬프트는 원본 얼굴, 긴 헤어의 볼륨, 편한 면 상의, 부드럽고 넉넉한 바지 핏, 원래 손목 보호대의 스트랩·엄지 구멍을 고정한다. 지수는 원본 재킷의 봉제선·지퍼·시보리, 데님 질감, 운동화, 가방 구조를 유지하도록 구체화한다.

## 입력 대응

각 인물은 원본 `LoadImage 7 → TextEncodeQwenImage21 16 images.image_1`을 유지한다. 같은 원본이 `LoadImage 7 → ImageCrop 34 → TextEncodeQwenImage21 16 images.image_2`로도 입력된다. 이름만 표기한 얼굴 참조가 아니라 실제 연결된 원본의 크롭이다.

워크플로우는 `workflows/`, 실제 프롬프트는 `prompts/`, 원본 복사본은 `references/`에 있다. 사용자 제공 원본 워크플로우와 v01 사본은 보존했다. 새 사본 두 개는 로컬 서버에서 오류·경고 없이 검증됐다.

## 생성 후 확인

두 인물을 2560×1536으로 실제 생성하고 v01·선택 원본과 비교했다. 서윤은 정면 얼굴과 바지의 부드러운 드레이프가 원본에 더 가까워 보이며, 두 인물의 머리카락·옷 봉제선·천 질감이 더 선명하게 관찰된다. 여러 옵션과 프롬프트를 함께 바꿨으므로 특정 옵션 하나의 효과나 객관적 품질 향상 수치로 주장하지 않는다.

서윤 첫 HQ 결과에서 후면 보호대가 누락됐다. `CHAR_01_rear_brace_repair.json`은 시트의 세 번째 640×1536 패널을 Comfy ImageCrop으로 추출해 Qwen에 실제 수정 대상으로 입력하고, 확정 원본의 손목 보호대 부분을 두 번째 참조로 입력한다. Qwen이 후면 왼손목 보호대를 복구한 후 ImageCompositeMasked로 원래 시트에 넣었다. 실제 후면 보호대와 반대쪽 맨손목을 육안 확인했다. 나머지 세 패널의 픽셀 보존은 `METADATA_CHECKS.json`에 기록했다. 이미지 크롭·수정·합성은 ComfyUI 노드가 수행했으며 Python은 설정·메타데이터·픽셀 비교만 수행했다.

추천 결과는 `outputs/CHAR_01_서윤_turnaround_v02_HQ_repaired.png`, `outputs/CHAR_02_도현_turnaround_v02_HQ.png`, `outputs/CHAR_03_지수_turnaround_v02_HQ.png`이다. 비교 페이지 `index.html`은 세 인물을 표시한다. 워크플로우는 기본 HQ 세 개와 서윤 후면 보완 한 개, 실행도 총 네 번이다.

후속 사용자 요청으로 도현도 같은 옵션으로 재생성했다. 확정 D 원본과 실제 입력의 해시 일치를 확인했고, 정면·양측면·후면 및 머리카락·셔츠 주름·단추·구두 디테일을 관찰했다. 시계는 정면·왼쪽을 향한 측면·후면 모두 해부학적 왼손목에 유지된다. 후면은 주머니 자세 지시와 달리 양팔을 내렸으며, 나머지 세 방향은 주머니 자세를 유지한다. 원본과 워크플로우는 `references/D11_CHAR_02_FINAL.png`, `workflows/CHAR_02_turnaround_HQ.json`이고 실제 프롬프트는 `prompts/CHAR_02.txt`이다.

생성·검수 상태와 사용자 최종 채택은 `RUNS.json`, 입력 해시·실제 참조 연결·프롬프트·샘플링 설정 대조는 `METADATA_CHECKS.json`에 있다. 측면·후면 세부 형상과 가방 뒷면은 원본에서 추정해 생성했으며, 이제 사용자가 작품의 인물 디자인으로 채택했다.

- 캐릭터 외형·의상·목소리·룩 등 고정 조건과 장면별 대사·행동·감정 등 변경 조건을 구분한다. 확정된 고정 조건을 임의로 바꾸지 않는다.

### 3.2 참조 자료의 역할 분리

- 예: `CHAR_A`, `CHAR_B`, `LOC_01`, `PROP_01`처럼 안정적인 ID를 사용한다.
- 실제 도구에서 이미지 순서·참조 슬롯·자산 ID를 확인하고 대응표를 작성한다.
- 의상 참조, 얼굴 참조, 배경 참조가 무엇을 결정하는지 분명히 한다.

- 파일명이나 `@태그`를 적은 것만으로 생성 도구에 자산이 연결되지는 않는다.

### 3.3 시작·종료 상태와 인계

최소한 인물별 위치·자세·시선·표정, 소도구의 소유자·위치, 진행 중인 행동과 대사 순서를 기록한다. 필요한 장면에는 좌우 배치, 이동 방향, 조명 방향, 화면 크기를 추가한다.

종료 상태는 다음 구간의 시작 조건이 된다. 텍스트 연결은 의미상 연속성 설계이며 픽셀 단위 프레임 일치를 보장하지 않는다. 정밀한 매치컷이 필요하면 해당 도구가 지원하는 프레임 참조나 편집 방법을 확인한다.

기획 상태와 관찰 상태는 별도로 기록한다. 생성물이 계획과 다르면 이전 결과를 수정할지, 실제 결과를 다음 구간으로 넘길지 판단한 뒤 인계를 갱신한다. 의도만 다음 구간에 복사해 오류를 누적하지 않는다.

### 3.4 대사와 행동

- 먼저 대사의 발화 길이를 잡고 그 안에 가능한 행동을 배치한다.
- 중요한 단어 1~3개에 표정·시선·손짓을 연결한다. 모든 단어에 동작을 붙일 필요는 없다.
- 한 구간에 여러 인물이 동시에 말하거나 복잡한 동작을 수행하면 순서를 분리하거나 구간을 나눈다.
- 번역 후에는 언어별 발화 길이와 강조 단어를 다시 배분한다.
- 음색의 자연어 설명은 실제 음성 ID와 구분한다. 설명 반복만으로 동일 목소리가 유지됐다고 주장하지 않는다.
- 별도 더빙을 쓰는 작업에는 최종 대사·타이밍을 더빙 자료에 넘기고, 영상 프롬프트에는 필요한 입 동작과 연기 지시만 담는다.

### 3.4.1 감정 변화의 세밀한 연기 설계

상태: 사용자 확정 제작 선호 (2026-10-05, 감정 연기 이미지 테스트 후). 아래는 출처 작성자의 지시나 모델의 검증된 성능이 아니라 이 프로젝트의 프롬프트 작성 기준이다.

연기를 '눈물을 흘린다', '분노한다', '슬퍼한다' 같은 감정명·결과 행동만으로 끝내지 않는다. 상황과 인물의 의도를 바탕으로 감정이 생기고 드러나는 과정을 관찰 가능한 행동으로 구체화한다.

- **계기와 시작 상태:** 무엇을 듣거나 보았는지, 직전의 감정·시선·자세를 적는다.
- **내적 반응과 억제:** 인물이 감추려는 것, 드러내려는 것, 상대에게 보이려는 태도를 정하고 실제 행동과 연결한다.
- **변화 순서:** 눈빛·시선·입술·턱의 긴장·호흡·자세 중 장면에 필요한 소수의 변화를 선택한다. 순서와 속도를 쓰되 모든 부위에 동시에 동작을 붙이지 않는다.
- **복합 감정과 강도:** 기쁨 속 불안, 슬픔을 감추는 미소 등 상황에 필요한 공존을 허용한다. 눈물을 슬픔과, 분노를 고함과 자동으로 연결하지 않는다. 절제 여부는 장면에 맞춘다.
- **종료와 잔여 감정:** 마지막 표정과 남은 긴장·시선·호흡, 다음 말이나 행동으로 이어질 상태를 적는다.

영상은 변화의 순서와 전환을 설계하고, 정지 이미지는 그 과정 중 선택한 한 순간의 보이는 상태만 요구한다. 구도 밖의 동작을 넣지 않는다. 시간·횟수의 자연어 지시가 정확한 실행을 보장한다고 취급하지 않는다.

감정의 따뜻함·강렬함과 고정된 피부색·노출·조명·질감을 구분한다. 의도한 얼굴 근육 움직임은 허용한다. 생성 후에는 감정 단계의 구분·자연스러움과 얼굴·룩 보존을 각각 확인한다. 이미지 테스트의 성공을 영상 전환의 성공으로 기록하지 않는다.

예시 — 안도의 눈물: 안전하다는 말을 듣기 전에는 입술을 다문 채 상대의 얼굴을 살핀다. 말을 듣고도 잠시 시선이 머문다. 짧은 날숨과 함께 턱의 긴장이 풀리고 눈 밑에 수분이 고인다. 울음을 감추려 입술을 한 번 눌렀다가 입꼬리가 작게 올라간다. 마지막에는 한쪽 눈물이 흐르는 동안 상대를 바라보며 미소를 유지한다. 이 순서·동작을 다른 장면에 일괄 적용하지 않는다.

### 3.5 룩과 카메라

- 장면군의 광원 방향·부드러움·색조·노출과 재질별 강조 관계를 일관되게 쓴다.
- 숫자를 쓸 때는 시각적 의도를 함께 적는다. 예: '금속 반짝임은 또렷하게, 피부와 천의 광택은 억제'.
- 원문 수치와 렌즈값은 참고 예시이며 모델의 실제 제어값이 아니다.
- 컷 생성에는 컷 순서와 전환을, 원테이크에는 연속 이동과 컷 금지를 명시한다.
- 카메라·인물·소도구·효과를 동시에 과도하게 움직이지 않는다. 복잡한 장면의 분할 여부는 작품 요구와 생성 결과에 따라 판단한다.

### 3.6 허용 요소와 금지 지시

- 등장인물·배경·소도구의 허용 목록을 먼저 쓴다.
- 주연, 반응만 하는 인물, 배경 인물의 역할을 구분한다.
- 전체 구간의 제한과 특정 컷의 제한을 구분한다.
- 예측되거나 실제로 관찰한 오류만 구체적으로 겨냥한다. 예: 의상 색 변경, 소도구 소실, 배경 인물 발화.
- 컷별 반복은 원문에 보이는 방법이지만 효과를 보장하지 않는다. 생성 도구의 길이 제한과 결과에 맞춰 조절한다.
- 허용한 효과를 금지 목록에서 다시 금지하는 등 충돌하는 지시를 정리한다.

### 3.7 오디오와 화면 문자

최종 완성본과 편집용 생성 클립의 요구를 구분한다. 별도 지시가 없는 편집용 클립은 불필요한 자막·워터마크·BGM을 배제하고, 필요한 대사·환경음·효과음만 명시한다. 최종본에 필요한 자막·음악은 사용자 요청과 편집 계획에 따른다.

| T2I는 완성 이미지의 관찰자 서술 | 중립 얼굴·구도·시선·배경을 현재형으로 묘사 |
| Edit는 변경 작업부터 시작 | Change only the woman's expression and tear state로 시작 |
| 유지 조건은 간결하게, 인물은 참조로 지정 | 동일한 유지 문장 하나 사용. 얼굴 생김새를 매번 재설계하지 않음 |
| 단일 참조에는 이미지 태그를 쓰지 않음 | the image로 지칭. 실제 파일 연결은 별도로 확인 |
| 숫자형 화면비·해상도는 본문 밖 | Mode / Aspect ratio / Prompt 입력 안내는 PROMPT_SETTINGS.md에 분리 |
| 별도 네거티브 대신 본문 요구 사항 | 긍정 조건 중심, 끝의 짧은 제외 문구. Qwen negative_prompt는 빈 값 |
| 근접 구도에 맞는 가장자리·조명 설명 | 얼굴·상단 어깨만 보이며 배경 소품을 추가하지 않음 |

가이드의 T2I 400~500단어·약 20문장 권고는 강제하지 않는다. 이번 목적은 단순한 얼굴 기준 이미지여서, 길이를 채우려고 배경·소품을 늘리면 비교 변수가 증가한다. Edit의 간결함도 감정 지시를 생략한다는 뜻으로 적용하지 않는다. 눈물의 위치, 입꼬리 변화, 눈가와 볼의 반응, 닫힌 입은 구체적으로 남긴다.

얼굴 동일성 유지는 얼굴 근육의 움직임을 전부 금지하는 뜻이 아니다. 눈꺼풀·볼·입술의 의도한 표정 변화는 허용하고, 다른 사람으로 바뀌는 형태·정체성의 변화를 따로 검수한다.

## 제안 캐릭터와 구도

가상의 30대 한국 여성 한 명, 어깨 길이 검은 머리, 아이보리 면 블라우스, 회색 실내 배경, 화면 왼쪽의 부드러운 빛을 테스트용으로 제안한다. 작품의 확정 캐릭터 설정은 아니다.

눈·입·턱이 선명한 정면에 가까운 얼굴 클로즈업. 이마와 턱은 프레임 안에 남기고 시선은 렌즈 옆의 상대에게 둔다. 모든 Edit에서 같은 위치·시선을 유지한다.

목표 화면비는 16:9. Qwen 사본의 수동 출력 크기는 1536 × 864이며, 원본 JSON의 1344 × 768(7:4)과 다르다. 가이드의 크기 예시보다 정확한 화면비라는 테스트 조건을 우선한다. GPT 앱에서 동일 크기를 설정할 수 없다면 실제 차이를 기록한다.

## 단계 1 — 중립 T2I 비교

prompts/00_NEUTRAL_T2I.txt의 전체 본문을 A와 B에 그대로 제출해 각 한 장을 만든다.

목표: 편안한 중립 얼굴, 눈·입의 가시성, 조명·시선·피부 질감을 확인하고 이후 실험의 기준 이미지를 확보한다. 예쁜 인물 여부만으로 채택하지 않는다.

서로 다른 모델에 같은 텍스트를 넣어도 같은 사람은 보장되지 않는다. 두 중립 얼굴이 다른 것을 감정 편집의 얼굴 유지 실패로 판정하지 않는다.

## 단계 2 — 같은 이미지에서 감정 Edit 비교

실제 결과를 확인한 뒤 공통 기준 이미지 하나를 고른다. 기존 캐릭터 이미지도 사용할 수 있다. 참조가 어느 도구에서 생성됐는지 기록한다.

두 도구에 정확히 같은 파일을 연결하고 다음 세 본문을 각 한 번씩 독립 실행한다.

| 상태 | 파일 | 필수 시각 상태 |
| --- | --- | --- |
| 01 눈물 맺힘 | prompts/01_TEARS_EDIT.txt | 아래 눈꺼풀에 물기, 입꼬리는 수평, 볼은 마름 |
| 02 미소 시작 | prompts/02_SMILE_EDIT.txt | 눈가·볼·입꼬리에 작은 미소, 눈물은 맺힘, 볼은 마름 |
| 03 눈물 흘림 | prompts/03_TEAR_FALL_EDIT.txt | 따뜻한 작은 미소, 한쪽 볼의 한 방울과 한 줄기 젖은 자국 |

세 상태 모두 입술은 닫혀 있고 치아는 보이지 않는다. 이는 치아 노출이라는 추가 변수를 줄이기 위한 첫 테스트 조건이며 모든 기쁨 연기의 기본 규칙은 아니다.

모든 Edit는 같은 중립 파일에서 시작한다. 01 결과를 02에, 02 결과를 03에 연결하지 않는다. 첫 테스트에서는 편집 오류의 누적을 막고 각 표정의 구현을 비교한다. 실제 장면 연결은 별도 테스트에서 다룬다.

관리용 ID는 CHAR_TEST_01이며 실제 기준 파일은 아직 없다. GPT에는 그 파일을 편집 대상으로 첨부한다. Qwen JSON에서는 LoadImage(node 7)의 IMAGE가 TextEncodeQwenImage21(node 16)의 images.image_1에 연결된다. 실제 기준 파일을 선택하고 참조 전달 여부를 확인해야 한다. 텍스트 ID나 기본 파일명 reference_1.png만으로 연결 완료라고 기록하지 않는다.

초회 제안 출력: 중립 T2I 두 장 + 감정 Edit 여섯 장 = 여덟 장.

## 실제 입력과 워크플로우

PROMPT_SETTINGS.md에서 Mode / Aspect ratio / Prompt 구분과 노드별 설정을 확인한다. 실제 프롬프트에는 각 .txt 본문만 넣는다.

Qwen 중립 테스트 사본: workflows/Qwen_Emotion_AB_00_T2I.json

사본에는 원본 모델·노드 연결·Prompting Guide를 보존하고 중립 본문, 정확한 목표 크기, 고정 시드 모드, 출력 접두사를 반영했다. 아직 ComfyUI에서 불러와 실행하지 않았다. 사본의 고정 시드는 Qwen 안에서 반복 조건을 기록하기 위한 것이며 GPT와 동일한 난수 조건을 만든다는 의미가 아니다.

Edit는 실제 기준 파일을 선택하고 node 7의 우회 상태를 해제한 뒤 실행한다. 원본에 없는 얼굴 교체, 자동 보정, 업스케일, 재배선은 추가하지 않는다. node 16의 resolution=1024는 캔버스 크기와 구분해 기록한다.

## 관찰과 판정

| 항목 | 확인 방법 |
| --- | --- |
| 감정의 읽힘 | 각 이미지를 따로 보고 안도·기쁨이 읽히는지, 슬픔·공포와 혼동되는지 기록 |
| 상태 구분 | 01/02/03의 미소와 눈물 위치가 의도대로 다른지 기록 |
| 얼굴 유지 | 기준 이미지와 비교해 같은 인물인지 확인. 의도한 표정 움직임과 얼굴 훼손을 구분 |
| 절제와 자연스러움 | 억지 울상, 과장된 미소, 부자연스러운 눈·입의 조합 확인 |
| 물리적 표현 | 눈물이 피부 표면에 있는지, 유리·플라스틱처럼 보이거나 피부가 녹는지 확인 |
| 고정 조건 | 구도·시선·헤어·의상·배경·빛의 방향 유지 확인 |
| 톤·디테일 보존 | 원본 대비 피부 톤·노출·배경 색과 피부·머리카락의 미세 질감 변화 확인. 같은 픽셀 크기를 화질 유지의 증거로 사용하지 않음 |

가능하면 도구 이름을 가리고 먼저 감정과 얼굴 유지 여부를 비교한다. 계획한 감정은 결과 관찰과 별도로 기록한다. 한 장의 우연한 성공으로 도구의 우열이나 성공률을 단정하지 않는다. 차이가 눈에 띄는 조건을 같은 문구로 반복한 뒤 다음 수정 항목을 정한다.

## 생성 후 기록

각 출력에 조건(A/B 및 00/01/02/03), 실제 모델·워크플로우 버전, 실제 설정·시드, 입력 파일, 제출 본문, 출력 파일·크기, 생성 횟수, 관찰된 감정·얼굴·눈물·종료 상태, 채택 여부와 다음 변경 항목을 기록한다. 현재 이미지 여덟 장의 관찰과 확인 가능한 생성 기록은 위 결과 문서 및 같은 폴더의 IMAGE_METADATA.json에 저장했다. 실제 총 생성 횟수·채택 여부·GPT 편집 연결은 아직 확인하지 않았다.

첫 테스트는 얼굴 감정의 정지 상태를 확인하는 단계다. 그 결과를 근거로 이후 영상에서 사용할 시작 상태·감정 변화·종료 상태를 설계한다. 영상 도구는 아직 정하지 않았다.
