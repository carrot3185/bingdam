# 감정 표현 이미지 A/B 테스트 01

작성일: 2026-10-05
프롬프트 버전: v2 — Deno 워크플로우 내 Prompting Guide 적용.
상태: 사용자가 생성한 이미지 여덟 장을 2026-10-05에 검수했다. Qwen 내장 프롬프트·참조 입력 기록도 확인했다. 영상 생성·영상 검수는 미실행.

실제 결과와 관찰: `_테스트/1. 인물/1. 감정연기/IMAGE_AB_REVIEW.md`. 두 도구가 서로 다른 기준 인물로 생성·편집해 이번 라운드는 각 도구 내 감정 변화와 얼굴 유지 검수로 기록한다. 같은 얼굴을 입력한 도구 간 비교는 아직 실행하지 않았다.

## 우선순위와 사용자 확정 조건

이번 테스트의 목적을 가장 우선한다. Prompting Guide는 문장 구성과 입력 형식의 기준으로 사용하며, 감정의 미세한 차이를 지우거나 장면 묘사를 불필요하게 늘리는 이유로 사용하지 않는다.

1. 같은 얼굴에서 안도와 기쁨이 읽히는가.
2. 눈물 맺힘 → 작은 미소 → 한 방울의 눈물이라는 세 상태를 구분해 만들 수 있는가.
3. 의도한 표정 변화 중에도 얼굴 동일성·구도·헤어·의상·조명이 유지되는가.
4. 동일한 본문과 같은 편집 입력에서 두 도구의 차이가 어떻게 나타나는가.

- A: OpenAI GPT Image 2.5, 사용자 지정 데스크톱 앱.
- B: Deno Qwen-Image 2.1 T2I + Edit, ComfyUI Desktop.
- 각 조건마다 두 도구에 동일한 영문 프롬프트 본문을 사용한다.
- 한쪽에만 디테일, 네거티브 프롬프트, 품질 강화 문구를 추가하지 않는다.
- 실제 앱의 자동 재작성·전처리·리사이즈가 있으면 기록한다. 사용자가 같은 문구를 제출하는 것과 내부 처리까지 동일한 것은 구분한다.

- 사용자 제공 워크플로우: D:/Comfy-Desktop/ComfyUI-Installs/KSH/ComfyUI/user/default/workflows/Deno Qwen-Image 2.1 T2I + Edit.json
- Prompting Guide: 위 JSON의 node 33, MarkdownNote.

가이드를 읽고 JSON에 저장된 노드·입력·설정을 확인했다. 모델 실행·노드 내부 동작·생성 성능은 확인하지 않았다. 가이드의 설명은 작성자의 지침이며 이 프로젝트에서 검증한 성능 결과가 아니다. 원본 워크플로우는 수정하지 않았다.

정지 이미지에서는 감정의 읽힘, 눈과 입의 관계, 눈물 표현, 과장 여부, 얼굴 유지 여부를 평가한다. 호흡·표정 변화 속도·미세 움직임·음성·시간적 연속성은 후속 영상 실험의 대상이다. 세 이미지를 나열하는 것만으로 자연스러운 연기를 검증했다고 기록하지 않는다.

## Prompting Guide 적용 방식

| 가이드의 큰 틀 | 이번 테스트 적용 |
| --- | --- |
| 영문 자연어 본문 | GPT와 Qwen에 동일한 영문 본문 입력 |
| T2I는 완성 이미지의 관찰자 서술 | 중립 얼굴·구도·시선·배경을 현재형으로 묘사 |
| Edit는 변경 작업부터 시작 | Change only the woman's expression and tear state로 시작 |
| 유지 조건은 간결하게, 인물은 참조로 지정 | 동일한 유지 문장 하나 사용. 얼굴 생김새를 매번 재설계하지 않음 |
| 단일 참조에는 이미지 태그를 쓰지 않음 | the image로 지칭. 실제 파일 연결은 별도로 확인 |
| 숫자형 화면비·해상도는 본문 밖 | Mode / Aspect ratio / Prompt 입력 안내는 PROMPT_SETTINGS.md에 분리 |
| 별도 네거티브 대신 본문 요구 사항 | 긍정 조건 중심, 끝의 짧은 제외 문구. Qwen negative_prompt는 빈 값 |
| 근접 구도에 맞는 가장자리·조명 설명 | 얼굴·상단 어깨만 보이며 배경 소품을 추가하지 않음 |

가이드의 T2I 400~500단어·약 20문장 권고는 강제하지 않는다. 이번 목적은 단순한 얼굴 기준 이미지여서, 길이를 채우려고 배경·소품을 늘리면 비교 변수가 증가한다. Edit의 간결함도 감정 지시를 생략한다는 뜻으로 적용하지 않는다. 눈물의 위치, 입꼬리 변화, 눈가와 볼의 반응, 닫힌 입은 구체적으로 남긴다.

얼굴 동일성 유지는 얼굴 근육의 움직임을 전부 금지하는 뜻이 아니다. 눈꺼풀·볼·입술의 의도한 표정 변화는 허용하고, 다른 사람으로 바뀌는 형태·정체성의 변화를 따로 검수한다.

## 제안 캐릭터와 구도

가상의 30대 한국 여성 한 명, 어깨 길이 검은 머리, 아이보리 면 블라우스, 회색 실내 배경, 화면 왼쪽의 부드러운 빛을 테스트용으로 제안한다. 작품의 확정 캐릭터 설정은 아니다.

눈·입·턱이 선명한 정면에 가까운 얼굴 클로즈업. 이마와 턱은 프레임 안에 남기고 시선은 렌즈 옆의 상대에게 둔다. 모든 Edit에서 같은 위치·시선을 유지한다.

목표 화면비는 16:9. Qwen 사본의 수동 출력 크기는 1536 × 864이며, 원본 JSON의 1344 × 768(7:4)과 다르다. 가이드의 크기 예시보다 정확한 화면비라는 테스트 조건을 우선한다. GPT 앱에서 동일 크기를 설정할 수 없다면 실제 차이를 기록한다.

## 단계 1 — 중립 T2I 비교

prompts/00_NEUTRAL_T2I.txt의 전체 본문을 A와 B에 그대로 제출해 각 한 장을 만든다.

목표: 편안한 중립 얼굴, 눈·입의 가시성, 조명·시선·피부 질감을 확인하고 이후 실험의 기준 이미지를 확보한다. 예쁜 인물 여부만으로 채택하지 않는다.

서로 다른 모델에 같은 텍스트를 넣어도 같은 사람은 보장되지 않는다. 두 중립 얼굴이 다른 것을 감정 편집의 얼굴 유지 실패로 판정하지 않는다.

## 단계 2 — 같은 이미지에서 감정 Edit 비교

실제 결과를 확인한 뒤 공통 기준 이미지 하나를 고른다. 기존 캐릭터 이미지도 사용할 수 있다. 참조가 어느 도구에서 생성됐는지 기록한다.

두 도구에 정확히 같은 파일을 연결하고 다음 세 본문을 각 한 번씩 독립 실행한다.

| 상태 | 파일 | 필수 시각 상태 |
| --- | --- | --- |
| 01 눈물 맺힘 | prompts/01_TEARS_EDIT.txt | 아래 눈꺼풀에 물기, 입꼬리는 수평, 볼은 마름 |
| 02 미소 시작 | prompts/02_SMILE_EDIT.txt | 눈가·볼·입꼬리에 작은 미소, 눈물은 맺힘, 볼은 마름 |
| 03 눈물 흘림 | prompts/03_TEAR_FALL_EDIT.txt | 따뜻한 작은 미소, 한쪽 볼의 한 방울과 한 줄기 젖은 자국 |

세 상태 모두 입술은 닫혀 있고 치아는 보이지 않는다. 이는 치아 노출이라는 추가 변수를 줄이기 위한 첫 테스트 조건이며 모든 기쁨 연기의 기본 규칙은 아니다.

모든 Edit는 같은 중립 파일에서 시작한다. 01 결과를 02에, 02 결과를 03에 연결하지 않는다. 첫 테스트에서는 편집 오류의 누적을 막고 각 표정의 구현을 비교한다. 실제 장면 연결은 별도 테스트에서 다룬다.

관리용 ID는 CHAR_TEST_01이며 실제 기준 파일은 아직 없다. GPT에는 그 파일을 편집 대상으로 첨부한다. Qwen JSON에서는 LoadImage(node 7)의 IMAGE가 TextEncodeQwenImage21(node 16)의 images.image_1에 연결된다. 실제 기준 파일을 선택하고 참조 전달 여부를 확인해야 한다. 텍스트 ID나 기본 파일명 reference_1.png만으로 연결 완료라고 기록하지 않는다.

초회 제안 출력: 중립 T2I 두 장 + 감정 Edit 여섯 장 = 여덟 장.

## 실제 입력과 워크플로우

PROMPT_SETTINGS.md에서 Mode / Aspect ratio / Prompt 구분과 노드별 설정을 확인한다. 실제 프롬프트에는 각 .txt 본문만 넣는다.

Qwen 중립 테스트 사본: workflows/Qwen_Emotion_AB_00_T2I.json

사본에는 원본 모델·노드 연결·Prompting Guide를 보존하고 중립 본문, 정확한 목표 크기, 고정 시드 모드, 출력 접두사를 반영했다. 아직 ComfyUI에서 불러와 실행하지 않았다. 사본의 고정 시드는 Qwen 안에서 반복 조건을 기록하기 위한 것이며 GPT와 동일한 난수 조건을 만든다는 의미가 아니다.

Edit는 실제 기준 파일을 선택하고 node 7의 우회 상태를 해제한 뒤 실행한다. 원본에 없는 얼굴 교체, 자동 보정, 업스케일, 재배선은 추가하지 않는다. node 16의 resolution=1024는 캔버스 크기와 구분해 기록한다.

## 관찰과 판정

| 항목 | 확인 방법 |
| --- | --- |
| 감정의 읽힘 | 각 이미지를 따로 보고 안도·기쁨이 읽히는지, 슬픔·공포와 혼동되는지 기록 |
| 상태 구분 | 01/02/03의 미소와 눈물 위치가 의도대로 다른지 기록 |
| 얼굴 유지 | 기준 이미지와 비교해 같은 인물인지 확인. 의도한 표정 움직임과 얼굴 훼손을 구분 |
| 절제와 자연스러움 | 억지 울상, 과장된 미소, 부자연스러운 눈·입의 조합 확인 |
| 물리적 표현 | 눈물이 피부 표면에 있는지, 유리·플라스틱처럼 보이거나 피부가 녹는지 확인 |
| 고정 조건 | 구도·시선·헤어·의상·배경·빛의 방향 유지 확인 |
| 톤·디테일 보존 | 원본 대비 피부 톤·노출·배경 색과 피부·머리카락의 미세 질감 변화 확인. 같은 픽셀 크기를 화질 유지의 증거로 사용하지 않음 |

가능하면 도구 이름을 가리고 먼저 감정과 얼굴 유지 여부를 비교한다. 계획한 감정은 결과 관찰과 별도로 기록한다. 한 장의 우연한 성공으로 도구의 우열이나 성공률을 단정하지 않는다. 차이가 눈에 띄는 조건을 같은 문구로 반복한 뒤 다음 수정 항목을 정한다.

## 생성 후 기록

각 출력에 조건(A/B 및 00/01/02/03), 실제 모델·워크플로우 버전, 실제 설정·시드, 입력 파일, 제출 본문, 출력 파일·크기, 생성 횟수, 관찰된 감정·얼굴·눈물·종료 상태, 채택 여부와 다음 변경 항목을 기록한다. 현재 이미지 여덟 장의 관찰과 확인 가능한 생성 기록은 위 결과 문서 및 같은 폴더의 IMAGE_METADATA.json에 저장했다. 실제 총 생성 횟수·채택 여부·GPT 편집 연결은 아직 확인하지 않았다.

첫 테스트는 얼굴 감정의 정지 상태를 확인하는 단계다. 그 결과를 근거로 이후 영상에서 사용할 시작 상태·감정 변화·종료 상태를 설계한다. 영상 도구는 아직 정하지 않았다.
